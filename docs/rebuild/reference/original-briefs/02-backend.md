Ignore any tenant field in the request. **Reads run under RLS, not the service role:** for every read operation create the Supabase client with the caller's `Authorization` header and the anon key, so the database enforces visibility. 2. Every write requires `Idempotency-Key`. Store it with the caller's user id and a hash of the body in `idempotency_keys` (keyed by tenant, actor, key, operation). Same key + same body returns the stored response; same key + different body returns 409 with a `SeamError` (category conflict). Purge keys older than 24 hours.
3. Errors return the `SeamError` shape (code, category, retryable, customerFacing.key) – never raw database messages. **Logging:** log only operationId, tenant, documentId, status and duration. Never log a request body, a token, a signed URL or a file name.
