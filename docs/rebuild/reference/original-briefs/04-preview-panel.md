# Prompt 04 – Screen 2: preview side panel

Read AGENTS.md and docs/ui-references.md (Drive details panel 50679553, Dropbox viewer cc1df21b). Reply with a 5-line plan first, wait for OK.

Build the preview as a 356px right side panel on the Documents tab (collapses to 80px; remember state). Opens on row select, Space or Enter; closes on Esc; the list keeps its scroll and selection.

Panel structure (top to bottom):
1. Header: document name (Title 16 Medium), close, overflow. Status tag + pipeline tag (if not Ready) + "On hold" if applicable.
2. Action bar (one row, one primary only): primary depends on state: In review → "Approve" (same gate as the review screen and the server: `aria-disabled` with the visible reason "2 required details need checking" while any required detail is unconfirmed); Approved → "Make effective"; Draft → "Send for review"; otherwise "Download". Quarantined → no primary; only Delete and Report. Uploading/Scanning/Reading → no Download. Secondary: Download, Add version, Share/Access. Unavailable actions use `aria-disabled` (stay focusable) and show the reason as text under the bar as well as in the tooltip (e.g. "Delete unavailable: legal hold DSP-2026-031"). For seeded documents, Download opens a printable view of `sample_pages` (prototype has no stored file).
3. **Key facts block** before the page, so people answering a customer read facts, not pages: for contracts signature level, end date, renewal type and term (format like "Signed (advanced) · Ends 30 Jun 2030 · Renews manually" – an illustration, not seed data); for anything on hold "On hold: <reason>"; for expired items the date. **Source rule (same for key facts and the Details tab):** a value shows only when its `extraction_fields` row is accepted or edited (or, for types without extraction, from `characteristic`). A pending value shows "Not confirmed yet – see the page below" and scrolls to the line when clicked. Never show a pending AI-read value as a fact.
4. Preview area (aspect ~A4): renders the current version from `sample_pages` (lines at the y positions, plain page look). Zoom out/in, page n of m. States: Ready → page; Uploading/Scanning/Reading → progress with the step name and what is happening ("Scanning for viruses. This takes a few seconds."); Failed → cause in words + Retry (if retryable) + "Report a problem with this file" (the dialog of prompt 07); Quarantined → no preview, "This file was blocked", cause, Delete, "Report to security", never a download. Documents whose type `storesPersonalData` (KYC outcome): **no preview area at all**; show the outcome fields and the line "The original document stays with the verification provider." Uploaded files without `sample_pages` render page 1 of the stored PDF or image (or "Preview not available for this file type" with Download). If the server refuses content (423), say "This file can't be opened yet: it is still being checked" or "…it was blocked by the security scan". Never blank.
5. Tabs: Details | Versions | Activity. Details: key metadata grouped (Type, Number, Counterparty, End date – same source rule as key facts; Sensitivity; Signature level with "Evidence held by signature provider"; Related to (entity links); Retention (policy name, retain until; hold with reason); Owner). Versions and Activity tabs, "Add version", "Share/Access" and "Manage access" are built later (prompts 06 and 08): render each as `aria-disabled` with the visible text "Available in a later build", never as a dead control. The Expires column and the Details tab never show `valid_to` or `expiry_date` for extractable types; the end date comes only from the confirmed `endDate` detail. Under Details add "Who has access" summary line (avatars + "Inherited from Order O-7731 · 2 exceptions" + "Manage access" link).
6. Footer: "Last updated 5 Nov 2026, 15:02 by …". (Do not show "Opened by you just now".)

Behaviours: with the panel open, Up/Down arrows move through the list and the panel follows the selection (agents step through files instead of reopening each). Optional "Wider preview" toggle widens the panel to show a full page; if you add it, write the reason to `docs/decisions/<date>-wider-preview.md` (never edit DESIGN.md). A `view` event is recorded via `recordAccess` once a row has been open for 1.5 s (arrowing through rows does not flood the audit). Switching rows updates the panel without losing the active tab. Quick-look feel: panel opens within one frame; the preview image is lazy but never empty. If the user lacks rights for an action, it is visible but disabled with the reason (not hidden).

States: each pipeline state, each status, on hold, expired, signed (qualified) and unsigned, read-only role, and a document with no extraction.

Verify at 1440 and 1920, light and dark, keyboard only (Tab order, Esc to close, focus returns to the row), and report in one line.
