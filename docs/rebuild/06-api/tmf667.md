# TMF667 v4 Document Management API (connected systems)

Contract: `contracts/seams/tmf667-document.openapi.yaml`. Reference: `reference/rules/tmf667-mapper.ts`. Gateway behaviour is described below; the source is `src/services/tmf-gateway.ts` in the current app.

Base path: `/api/public/tmf-api/document/v4`. The legacy alias `/api/public/tmf-api/documentManagement/v4` answers identically, plus the headers `Deprecation: true` and `Sunset: <10 May 2027>`.

## Operations
| Method | Path | Scope | Standard? | Notes |
|---|---|---|---|---|
| GET | /document | read | TMF667 | Filters: `relatedEntity.id`, `relatedEntity.@referredType`, `documentType`, `status` (TMF values), `lifecycleState` (ERAD values), `fields`, `offset`, `limit` (default 20, max 100). Headers `X-Total-Count`, `X-Result-Count`. |
| POST | /document | register | TMF667 | Needs `Idempotency-Key` (8–128 of `[A-Za-z0-9-_]`). Attachment is inline base64 (≤5 MB) or a URL (≤25 MB, DNS-checked, no private addresses). Returns 201 and `Location`. |
| GET | /document/{id} | read | TMF667 | Supports `fields`. |
| PATCH | /document/{id} | register (other fields), or transition/approve (status only) | TMF667 | A `status` change follows the status path and the approve gate (BR-131). |
| DELETE | /document/{id} | delete | TMF667 | Soft delete, same blockers as BR-050. |
| POST | /document/{id}/transition | transition / approve | **ERAD extension** | Body `{to: lifecycleState}`. |
| POST | /document/{id}/legalHold | hold | **ERAD extension** | Place or release, with reason and reference. |
| GET | /document/{id}/attachment/{aid}/content | read | **ERAD extension** | Returns a short-lived download link `{url, expiresInSeconds: 60}`. 409 `contentLocked` while scanning or quarantined. |
| GET | /documentSpecification | read | TMF667 | The effective types for the key's tenant. |
| GET | /documentSpecification/{id} | read | TMF667 | |
| POST | /hub | subscribe | TMF688 pattern | `{callback, query?}`. Returns id and a one-time `secret`. The callback is DNS-checked. |
| DELETE | /hub/{id} | subscribe | TMF688 pattern | |
| POST | /oauth/token | – | OAuth 2.0 | `grant_type=client_credentials` with the system key. Returns `{access_token: eradt_…, token_type: Bearer, expires_in: 900, scope}`. |
| any | unknown path or method | – | – | TMF error JSON 404/405, never HTML. |

Authentication: `Authorization: Bearer <erad_ key | eradt_ token>`. Order of checks: key or token valid and not expired or revoked → scope → rate limit → operation. **Every query is pinned to the key's tenant.**

## Resource shape
- **Standard fields:** id, href, name, description, documentType, status (BR-130), creationDate, lastUpdate, version, attachment[], relatedEntity[] (`@referredType` uses SID names: BillingAccount, Quote, ProductOrder, Agreement, Customer, TroubleTicket, Site), characteristic[], externalIdentifier[], validFor, `@type`.
- **ERAD extensions,** declared by `@type: EradDocument` and `@schemaLocation`:
  - lifecycleState (internal status)
  - sensitivity
  - legalHold
  - retainUntil
  - attachment `contentHash` and `isCurrent`
- **Error:** `{code, reason, message, status: "<http>", "@type": "Error"}`. The full code list, from the gateway:
  - **400:** bodyTooLarge, idempotencyKeyMissing, invalidBody, invalidCallback, invalidContent, invalidJson, invalidQuery, invalidStatus, mimeNotAccepted, tooLarge, unknownDocumentType
  - **401 / 403:** unauthorized; scopeMissing
  - **404 / 405:** notFound, relatedEntityNotFound; methodNotAllowed
  - **409:** contentLocked, frozen, idempotencyMismatch, requiredDetailsPending, transitionNotAllowed
  - **413 / 415:** tooLarge; unsupportedMediaType
  - **422:** attachmentUnreachable, hashMismatch
  - **429 / 503:** tooManyRequests; unavailable

## Rate limiting
Each connected system has its own allowance per minute: reads 120 and changes 30 by default (BR-110–115). A 429 response carries a `Retry-After` header, the `RateLimit-*` headers, and a message such as: "This system has used its allowance of 30 changes per minute. Wait 12 seconds (see Retry-After) and send the request again. Other connected systems are not affected. …"

## Events
Envelope (TMF688 style): `{eventId, eventTime, eventType, correlationId, domain, title, description, priority, timeOcurred, event:{document:{id, href, status, lifecycleState?}}, changedAttributes?}`. The exact builder is in `reference/rules/tmf667-mapper.ts`.
- Request headers: `X-Signature`, `X-Signature-Timestamp` and `X-Event-Id`.
- `eventType` is one of the BR-127 names.
- Delivery rules are BR-120–126.

## Standard vs custom summary
- **Standard TMF667:** document CRUD, documentSpecification reads, the status enum, paging, fields, and the error object.
- **TMF688 pattern:** hub and listener, and the event names.
- **ERAD extensions (declared):** transition, legalHold, content link, lifecycleState, sensitivity, legalHold/retainUntil fields, contentHash, idempotency, and the signature headers.
- **Not provided:** DocumentSpecification writes (types are managed in the admin UI only), and creating related entities.
