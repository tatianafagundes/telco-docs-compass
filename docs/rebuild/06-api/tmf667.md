# TMF667 v4 Document Management API (connected systems)

Contract: `contracts/seams/tmf667-document.openapi.yaml`. Reference: `reference/rules/tmf667-mapper.ts`. Gateway behaviour is described below; the source is `src/services/tmf-gateway.ts` in the current app.

Base path: `/api/public/tmf-api/document/v4`. The legacy alias `/api/public/tmf-api/documentManagement/v4` answers identically, plus the headers `Deprecation: true` and `Sunset: <10 May 2027>`.

| POST | /document/{id}/attachment/{aid}/extractionResult | extract | **ERAD extension** | `{result: read\|unreadable, attempt, fields?}`; details saved as pending proposals (BR-160, BR-161, BR-167); body up to 1 000 000 bytes. |

| DELETE | /hub/{id} | subscribe | TMF688 pattern | |
| POST | /oauth/token | – | OAuth 2.0 | `grant_type=client_credentials` with the system key. Returns `{access_token: eradt_…, token_type: Bearer, expires_in: 900, scope}`. |

Authentication: `Authorization: Bearer <erad_ key | eradt_ token>`. Order of checks: key or token valid and not expired or revoked → scope → rate limit → for `scan` and `extract` keys, still the organisation's designated system (403 `notDesignated`, BR-163) → operation. **Every query is pinned to the key's tenant.**

## Resource shape
- **Standard fields:** id, href, name, description, documentType, status (BR-130), creationDate, lastUpdate, version, attachment[], relatedEntity[] (`@referredType` uses SID names: BillingAccount, Quote, ProductOrder, Agreement, Customer, TroubleTicket, Site), characteristic[], externalIdentifier[], validFor, `@type`.
- **ERAD extensions,** declared by `@type: EradDocument` and `@schemaLocation`. The schema is served by the app itself (`public/tmf-schemas/EradDocument.schema.json`), describes the whole Document as returned, and references nothing outside itself; a test checks real replies against it:
  - lifecycleState (internal status)
  - sensitivity
  - legalHold
  - retainUntil
  - attachment `contentHash` and `isCurrent`
- **Error:** `{code, reason, message, status: "<http>", "@type": "Error"}`. The full code list, from the gateway:
  - **400:** filterTooBroad, idempotencyKeyMissing, invalidBody, invalidCallback, invalidContent, invalidJson, invalidQuery, invalidStatus, mimeNotAccepted, tooLarge, unknownDocumentType
  - **401 / 403:** unauthorized (with a `WWW-Authenticate` header); scopeMissing, notDesignated, notRegisteredHere
  - **404 / 405:** notFound, relatedEntityNotFound; methodNotAllowed
  - **409:** cannotProcess, changedMeanwhile, contentLocked, fileMissing, frozen, hashMismatch (file results), idempotencyInProgress, idempotencyMismatch, notCurrent, notFetched, notReading, notScanning, notUploading, notYourStep, quarantined, requiredDetailsPending, sizeMismatch, staleAttempt, transitionNotAllowed, versionNotCurrent
  - **400 (file results):** unknownFields, duplicateFields, badValues (with `names`)
  - **413 / 415:** bodyTooLarge, tooLarge; unsupportedMediaType
  - **422:** attachmentUnreachable, hashMismatch
  - **429 / 503:** tooManyRequests; unavailable

## Limits on what a caller sends
Request bodies are read up to a limit and never in full: 50 KB, about 7 MB for a registration with inline content, 4 KB for the token request. A body over the limit is answered 413 `bodyTooLarge`. A filter on a record that matches more than 1000 documents is answered 400 `filterTooBroad` instead of a partial list. `externalIdentifier.owner` narrows `externalIdentifier.id`. A system holds at most 10 live access tokens, and token requests are limited per caller address and per system (429 `temporarily_unavailable` with `Retry-After`).
## Rate limiting
Each connected system has its own allowance per minute: reads 120 and changes 30 by default (BR-110–115). A 429 response carries a `Retry-After` header, the `RateLimit-*` headers, and a message such as: "This system has used its allowance of 30 changes per minute. Wait 12 seconds (see Retry-After) and send the request again. Other connected systems are not affected. …"

## Events
Envelope (TMF688 style): `{eventId, eventTime, eventType, correlationId, domain, title, description, priority, timeOcurred, event:{document:{id, href, status, lifecycleState?}}, changedAttributes?}`. The exact builder is in `reference/rules/tmf667-mapper.ts`.
- Request headers: `X-Signature`, `X-Signature-Timestamp` and `X-Event-Id`.
- `eventType` is one of the BR-127 names, plus the file events `DocumentFileStoredEvent`, `DocumentFileReadyToReadEvent` and `DocumentFilePurgedEvent` (declared extensions, BR-150, BR-151): sent only to subscriptions that name them, with whitelisted facts under `event.file`, written by the database trigger.
- Delivery rules are BR-120–126.

## Standard vs custom summary
- **Standard TMF667:** document CRUD, documentSpecification reads, the status enum, paging, fields, and the error object.
- **TMF688 pattern:** hub and listener, and the event names.
- **ERAD extensions (declared):** transition, legalHold, content link, confirm upload, scan and extraction results, file events, lifecycleState, sensitivity, legalHold/retainUntil fields, contentHash, idempotency, and the signature headers.
- **Not provided:** DocumentSpecification writes (types are managed in the admin UI only), and creating related entities.
## The organisation's own antivirus and reader
How a system with `scan` or `extract` works with the API, step by step, with examples: `docs/integration/tmf667-api.md` ("The organisation's own antivirus and reader"). Rules: BR-150–169. Residual risk: a wrong or compromised scanner cannot be told apart from a correct one; the controls (one designated key, download receipt, hash of the stored bytes, attempt and version binding, quarantine-rate alert) limit what it can do. A human security review approves before release, and a privacy (and AI, if the reader is AI) impact assessment is for the customer.
