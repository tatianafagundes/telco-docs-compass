# P5b — Accessibility gaps: prototype vs rebuild spec (listing only)

Scope: `/Users/earatat/telco-docs-compass`, branch `review/multi-perspective-2026-11`, static read of `src/components/{erad,search,documents,review,upload,holds,admin,access}`, `src/routes`, `src/styles.css`, `src/styles/tokens.css`, `src/lib/document-labels.ts`, against `docs/rebuild/14-non-functional.md`, `docs/rebuild/13-angular-frontend.md`, `docs/rebuild/17-kiro-steering/invariants.md` (item 12), `docs/rebuild/05-screens/*.md`, `docs/rebuild/15-test-strategy.md`, and the kit rules in `Document Management/AGENTS.md` and `Document Management/DESIGN.md`. Nothing was run, nothing was edited. Contrast ratios below were computed numerically from the hex values in `tokens.css` (WCAG relative-luminance formula); every other claim is from reading the code.

Method: the `fixing-accessibility` checklist (names, keyboard, focus and dialogs, semantics, forms, announcements, contrast and states, motion) applied file by file, listing mode.

Verdict keys: **BLOQUEIA** = AA failure or invariant 12 break the rebuild would copy if it ports the prototype as is. **CORRIGIR** = AA gap the spec must state explicitly so the rebuild does not copy it (or so the rebuild does not drop the fix). **NOTA** = best practice.

Overall: the prototype is a good behavioural reference for keyboard paths, focus return, `aria-disabled` + reason, live regions and landmarks. It is **not** a safe colour reference: four token pairings fail 4.5:1 (one in light theme, three in dark), and one family of buttons breaks invariant 12 (unavailable with no visible reason). The spec currently says "contrast AA in both themes" and "show their reason" without naming the pairs or the buttons, so the rebuild would copy all five.
