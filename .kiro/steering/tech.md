# Technology

- TanStack Start (React 19, TanStack Router and Query), Vite, Tailwind 4, zod, Vitest, bun. Backend: Supabase (Postgres with row-level security, Auth, Storage). Hosting build output is generated by Nitro.
- Commands: `bun run dev`, `bun run check` (eslint, `tsc`, tests, build), `bun run test`. `RUN_ACCESS_TESTS=1 bun run test` also runs read-only checks against the real backend.

## Conventions

- **Screens never call the database.** They use a hook, which calls `src/services/api.ts`, which calls a server function (`*.functions.ts`, `createServerFn` with `requireSupabaseAuth`). Server functions return `SeamResult` and do not throw to the screen.
- **Reads** run as the caller (row-level security applies). **Writes** use the privileged client only after `runWrite` has checked that the document is visible and belongs to the caller's tenant, and after the handler has checked the role. Each write records its own activity entry. The TMF gateway and the bulk worker are the two other write paths and scope every query to one tenant.
- **Business rules are pure functions** (no I/O) with a test next to them in `src/services/__tests__`. Server functions call them; they do not repeat them.
- **Database answers** are checked: `must(await query, "what you were doing")`. Never use only `data`.
- Never `select("*")` on `documents`: the generated search column breaks the types.
- Colours exist only in `src/styles/tokens.css`; components use the token utilities. Design-system primitives are in `src/components/erad/`.
- Tests: write the test first, see it fail for the right reason, then fix. Service tests use `FakeDb` from `src/test/fake-db.ts`. It does not enforce row-level security; say so in the test when it matters.
- Dependencies: pin versions, prefer well-known maintained packages, and say why a new one is needed.
- Limits and time constants are named constants with a comment that says why they have that value.
